МЕТОДИКА
Что показывает GraphLens.
От запроса к карте покрытия
Автотест отправляет GraphQL-запрос на адрес прогона. Прокси разбирает запрос с помощью GraphQL AST, сопоставляет его со снимком схемы, пересылает в API и сохраняет событие обращения. Интерфейс строит отчёт по этим событиям.
Как считается процент
Количество уникальных запрошенных полей делится на число полей объектных и интерфейсных типов, достижимых из Query и Mutation. Корневые поля входят в расчёт. Служебные поля __typename и introspection исключены.
Одно поле считается один раз в запросе, даже если встречается несколько раз под разными алиасами. Счётчик показывает число запросов, выбравших это поле. Директивы @skip и @include учитываются вместе с переменными и их значениями по умолчанию.
Условия и ограничения
Покрытие характеризует выбор полей запросами. Проверки значений в assertions и фактические вызовы резолверов требуют отдельной интеграции. Валидный запрос учитывается и при ошибке ответа API. Ошибки отражаются в журнале.
Для интерфейсов и union учитываются поля объявленных в запросе типов. Все выбранные ветки inline fragments входят в статическую метрику, даже если ответ содержит только один вариант типа. Типы входных объектов и подписки исключены из процента.
Поддерживаются HTTP JSON query и mutation, алиасы, фрагменты, operationName и переменные. WebSocket-подписки, multipart-загрузки, persisted queries без текста и batch-запросы находятся за пределами MVP.
История и конфиденциальность
Каждый прогон хранит свой снимок схемы. Разница покрытия вычисляется между прогонами с одинаковым снимком. В журнал сохраняется текст операции. Значения переменных и заголовки авторизации не сохраняются. Значения, записанные прямо в тексте запроса, остаются в журнале.
