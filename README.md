# GraphLens

GraphQL Coverage Proxy для кейса Zunami «Сеть глазами Бога».

Сервис принимает запросы автотестов, пересылает их в GraphQL API и показывает покрытие типов и полей схемы. В комплект входят учебный API магазина, два набора тестов и сценарий защиты.

## Быстрый запуск

Требуется Node.js 22.13+ или Node.js 24 LTS.

```bash
npm ci
npm start
```

Откройте http://localhost:3000. При первом открытии интерфейс создаёт демонстрационный прогон. Данные сохраняются в `data/graphlens.sqlite` и доступны после перезапуска. Порт задаётся переменной `PORT`, путь к базе — `DB_PATH`.

Альтернативный запуск через Docker Compose

```bash
docker compose up --build
```

Контейнер хранит SQLite в именованном томе. Docker-конфигурация подготовлена, запуск контейнера в среде разработки не проверялся.

## Демонстрация

1. Откройте «Покрытие». Базовый набор выполняет 3 запроса и покрывает 14 из 30 полей, округлённо 47%.
2. Нажмите на User. Поле email ещё не запрашивалось.
3. Нажмите «Расширить демо». Новый прогон выполняет 6 запросов и покрывает 27 из 30 полей, 90%.
4. Откройте историю и выберите оба прогона. Будут показаны 13 новых полей и рост округлённого процента на 43 п.п.
5. Останутся Mutation.updateProfile, Order.items и Order.customer. Откройте «Проверить запрос» и выполните

```graphql
mutation FinishCoverage {
  updateProfile(name: "Demo") {
    orders {
      items { quantity }
      customer { id }
    }
  }
}
```

Это поднимет расширенный прогон до 30 из 30 полей. Полное покрытие выбранных полей не характеризует полноту assertions тестов.

Для создания двух свежих прогонов из терминала выполните `npm run demo` при работающем сервере. Переменная `GRAPHLENS_URL` позволяет выбрать локальный адрес. Закрытый опубликованный сайт требует авторизации ChatGPT, поэтому для CI и демонстрации прокси с curl удобен локальный запуск.

## Подключение своего API

Откройте «Подключение API», задайте endpoint, название прогона, ветку и окружение. Схема загружается через introspection. При отключённом introspection вставьте SDL или загрузите `.graphql` файл. Заголовки формы используются только для introspection и не сохраняются.

После создания прогона скопируйте адрес `/proxy/<run-id>` и задайте его как GraphQL endpoint в автотестах. Передавайте нужную авторизацию API в каждом запросе. Заголовок `X-Coverage-Test` связывает поля с названием теста.

```bash
curl http://localhost:3000/proxy/RUN_ID \
  -H 'Content-Type: application/json' \
  -H 'X-Coverage-Test: profile.spec / email' \
  --data '{"query":"query { viewer { id name email } }"}'
```

Для защищённого API добавьте `Authorization`. В локальном режиме cookies пересылаются в API. Опубликованный вариант исключает cookie авторизации самого сайта и использует переданные API-заголовки. Для API внутри корпоративной сети запускайте GraphLens в доступной ему сети.

## Методика

- Единица покрытия — `Type.field`. Алиас относится к исходному имени поля.
- Знаменатель включает поля объектных и интерфейсных типов, достижимых из Query и Mutation, и сами корневые поля. Входные типы, introspection и `__typename` исключены.
- Каждое поле учитывается один раз на входящий запрос. Повторное выделение через алиас или фрагмент не увеличивает счётчик внутри одного запроса.
- Учитываются выбранная `operationName`, именованные и inline fragments, `@skip`, `@include`, переменные и значения по умолчанию.
- Невалидный документ или некорректные переменные дают запись об ошибке анализа с нулевым вкладом в покрытие. Исходный запрос передаётся API.
- Валидные выбранные поля учитываются независимо от статуса ответа API. Ошибки GraphQL и HTTP видны отдельно в журнале.
- Ветки фрагментов интерфейсов и union учитываются статически. Поле относится к типу, на котором оно объявлено в запросе. Данные ответа и фактический runtime-тип на покрытие не влияют.
- Счётчик типа означает количество запросов с его полями. В UI показывается доля покрытых полей каждого типа.
- Сохраняются выбранные аргументы и пути вложенности, максимальная глубина, операция и метка теста. Аргументы не включаются в общий процент полей.
- Каждый прогон хранит свой SDL-снимок и SHA-256. Сравнение разрешено для идентичных нормализованных снимков.
- `X-Coverage-Event-ID` позволяет повторно отправить одну запись без удвоения метрики. Повторный HTTP-запрос всё равно выполняется в upstream, включая mutation. Это идентификатор события статистики.

## Возможности и границы MVP

Работают HTTP query/mutation, загрузка SDL и introspection, граф схемы, таблица полей, журнал последних 200 запросов, привязка к тестам, история, фильтры по ветке/окружению, сравнение одинаковых схем и CSV/JSON-экспорт. Метрика агрегируется по всем событиям прогона, даже если в журнале показаны последние 200.

WebSocket-подписки, multipart upload, batch, APQ без текста, отслеживание assertions, распределённые трассировки и интеграция с GitLab CI требуют дальнейшей разработки. Фильтр даты и отдельный timeline не включены. Граф рассчитан на небольшие и средние схемы. Для больших объёмов нужна серверная агрегация событий и виртуализация графа.

В журнал сохраняется текст запроса. Заголовки и значения переменных не сохраняются. Секреты, записанные прямо в query как литералы, остаются в тексте. Локальный сервер рассчитан на контролируемую среду команды. Авторизация пользователей приложения предоставляется хостингом опубликованной версии.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/health` | Проверка доступности |
| GET / POST | `/api/runs` | Список или создание прогона |
| GET | `/api/runs/:id/coverage` | Снимок схемы и метрики |
| GET | `/api/runs/:id/executions` | Последние 200 запросов |
| GET | `/api/runs/:id/export?format=csv` | Экспорт CSV |
| GET | `/api/runs/:id/export` | Экспорт JSON |
| POST | `/proxy/:id` | GraphQL query или mutation |
| GET | `/proxy/:id?query=...` | GraphQL query, пересылается как POST |
| POST | `/api/demo` | Демо. Тело `{"extended":true}` включает расширенный набор |
| POST | `/demo/graphql` | Учебный GraphQL API |

POST `/api/runs` принимает `name`, `branch`, `environment`, `endpoint`, опциональные `sdl` и `headers`. Значение endpoint `demo` выбирает учебный API.

## Архитектура

`src/analyzer.mjs` разбирает документ и связывает AST со схемой через библиотеку GraphQL.js. `src/worker.mjs` содержит HTTP API, прокси и сбор событий. `scripts/server.mjs` адаптирует обработчик к Node.js и SQLite. В опубликованной версии тот же обработчик использует D1. `public/` содержит интерфейс без клиентского фреймворка. Схема базы находится в `migrations/` и её версии для публикации в `drizzle/`.

События добавляются отдельными INSERT, без перезаписи общей статистики. Это сохраняет счётчики при конкурентных запросах. Сбой записи статистики возвращает исходный ответ API с `X-Coverage-Status: storage-error`.
